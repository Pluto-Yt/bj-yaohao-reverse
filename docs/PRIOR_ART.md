## 〇、速览（先读这 12 行）

1. **算法身份不是本次首次发现。** 2014 年官方自己公布了摇号客户端，当年就有至少两篇独立反编译文指出实现是 **C# `System.Random` + `Random.Next(池大小)` + 撞重跳过**，并给出 2014 年首期完整参数（seed `026498` / 池 `2235804` / 配额 `20195`）。
2. 该客户端本体至今可复取：**Wayback 归档的官方分发端点与博客园附件逐字节相同**（zip SHA-256 `d6de5182…bf7e49`；内含 `CarQuotaNoPickPublic.exe` SHA-256 `afca5ff7…5ab67e`，反编译源码 `AssemblyInfo` 记 `AssemblyCompany("taiji")`、`版权所有 (C) taiji 2011`，与后来的中标方太极计算机股份有限公司吻合）。
3. 2016 年有人把算法写成 C# 源码贴在文章里（含 `Random random=new Random(period.Seed)` 与 `if(selecteddict.ContainsKey(selected.ID)) continue;`），并采集了 2011–2016 共 51 期池列表与种子。
4. 2017 年有人把 .NET `Random` **逐位移植成 PHP**（`(int)($this->sample()*$value)`），2019 年有人在协议层把这套机制完整写成文字（含 10⁶ 种子枚举的观察）。
5. **2024 年有人做过与本次最接近的黑箱复现**：用 2024 年 6 月种子 `463140` 逐位比对，第 925 位错位，据此判定"抽中已中签者就跳过"，并数出该期 53 个重号；续篇结论是"没有规律"。
6. 官方口径（"第三重随机"＝国标 GB/T 10111—2008 **规范性附录 C** 的线性同余发生器）有**两处互相独立的一手出处**，且最早可回溯到 **2011-01-27 人民日报**（当时叫"多重随机/双随机性"，专家称"基于国标 GB/T 10111—2008 的递推公式"）。
7. **公开世界没有人把"官方称 LCG"与"实测/官方程序实为 .NET Knuth 减法发生器"并列做过实证对照** —— 这是本次工作最硬的空白位。
8. **英文/国际学术界无人做过北京摇号算法的实现级逆向**（arXiv API 0 命中、OpenAlex/Semantic Scholar/Crossref 无相关）；英文文献一律把摇号当"天然随机实验"使用。
9. 必查的 2019 年万方论文**案例地是贵阳市，不是北京**，且它把线性乘同余法当作"待改进"对象 —— 不能当作官方口径的学术背书。
10. 必查的 2014 年政府采购 PDF 是**死链（404，Wayback 无捕获）**；但其 9 条功能条目已由 **2025-09 在职官方招标文件（全文可达，物理页 43）** 逐字证实；2021 年"摇号客户端"是**独立采购标的，单独报价 33 万元**，中标方太极计算机股份有限公司。
11. **本次检索期间实测扩展了可核验窗口**：2014 年第 1 期**单位**摇号可逐位精确复现（1300/1300 值+顺序全同），2014 年第 1 期**个人**摇号 20195 个基数序号 100% 落在生成流内且为严格递增子序列；而 2011、2013 年公示表**没有"摇号基数序号"列**，故可核验窗口自 2014 年起。
12. 因此本次工作的定位应改为：**首次在不使用官方程序/反编译产物、不预设种子、仅凭公开公示 PDF 的条件下，跨多期做一致性检验＋负对照，并首次把官方口径与实测算法族直接对立。**

## 八、结论（公开世界已知 / 未知 / 本次是第几份什么性质的证据）

1. **已知（一手可达）**：制度与流程（申报期、25 日入池封存、26 日配置、阶梯中签率、失信被执行人受限）；**官方口径**＝第三重随机是"国标 GB/T 10111—2008 规范性附录 C 的线性同余发生器"（办事指南层，非规章层）；**池构造规则**（按申请编码升序、阶梯接续分配多序号）；**"每编码最多中签一次"**是官方明文承诺；**2014-02-25 起官方曾公布摇号客户端＋摇号池编码文件＋MD5＋6 位种子**，并允许公众离线验算。
2. **已知（第三方一手）**：客户端是 **.NET Framework 2.0 的 C# 程序**，核心是 `new Random(Seed)` ＋ `Random.Next(池大小)` ＋ 撞重跳过；2014/2016/2017/2019/2024 已有至少五批互不相关的第三方独立做出同一判断（反编译、移植、协议描述、黑箱比对）；官方程序本体可在 Wayback 复取并已做字节级比对。
3. **已知（本次实测新增）**：可核验窗口自 **2014 年**起（2011/2013 年公示表无"摇号基数序号"列）；2014 年第 1 期单位摇号可**逐位精确复现**，个人摇号的 20195 个基数序号 100% 在生成流内且为严格递增子序列。
4. **还不知道（公开世界）**：现行版本（2020 年后）的具体实现是否仍与 2014 年客户端一致（本次黑箱结果与之一致，但**没有官方现行程序可对照**）；GB/T 10111—2008 **附录 C 的正文与参数**；官方"线性同余"口径与实际实现的差异是**换代**、**口径沿用**还是**表述错误**；第三方测评与验收结论；完整"序号↔申请编码"整期池映射是否对第三方开放。
5. **本次是第几份、什么性质**：它是**第 6 份以上**触及同一算法的公开工作，但是**第 1 份**"不使用官方程序/反编译产物、不预设种子、仅凭公开公示 PDF、跨多期、含显式负对照"的**黑箱实证**；并且是**唯一一份**把**官方宣称的国标线性同余口径**与**实测的 .NET Knuth 减法发生器**直接对立的证据。
6. **同时要说清的两条边界**：① 本次**没有**恢复任何一期的真实种子，也**不能**据算法提前预测结果（种子仍在摇号当天现场产生）；② 本次**没有**证明官方"作弊"——它证明的是"**官方对外口径与公开可核验的实现不一致**"，这是一个需要官方核证的口径问题，而非行为定性。
